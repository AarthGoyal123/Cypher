## Step-by-Step Implementation Guide

### Step 1: Explode Candidates & Join Text Data
Member 2 outputs candidates as a comma-separated list to save disk space. You must "explode" this into a long format where each row is a pair `(source1_id, target_id)`.

```python
# Pseudo-code for explosion:
df_candidates = pd.read_csv("candidate_pairs.tsv", sep="\t")
# Explode the comma-separated candidate_entity_ids into individual rows
df_candidates['target_entity_id'] = df_candidates['candidate_entity_ids'].apply(lambda x: x.split(',') if pd.notna(x) and x != "" else [])
df_pairs = df_candidates.explode('target_entity_id').dropna(subset=['target_entity_id'])
```
After exploding, perform a `pd.merge` to attach the `business_name_clean`, `business_address_clean`, and `country_clean` for *both* the Source 1 entity and the Target entity.

### Step 2: Target Label Generation (Training Mode)
Load `train_ground_truth.tsv`. If a `target_entity_id` exists in the `matched_entity_ids` list for a given `source1_entity_id`, label `is_match = 1`. Otherwise, `is_match = 0`. This is a hard boundary: do not allow target leakage!

### Step 3: Implement the 9 Frozen Features
You must implement the exact mathematical definitions below. Do not create ad-hoc features.

#### Feature 1: `feat_jaro_name`
*   **Method:** `jellyfish.jaro_winkler_similarity(s1_name, target_name)`
*   **Handling:** Fill NaNs with 0.0.

#### Feature 2: `feat_lev_name`
*   **Method:** $1.0 - \frac{\text{levenshtein}(s1, target)}{\max(\text{len}(s1), \text{len}(target), 1)}$
*   **Handling:** Use `jellyfish.levenshtein_distance`.

#### Feature 3: `feat_monge_elkan_name`
*   **Method:** Split names by whitespace into tokens $T_1$ and $T_2$. 
    $\frac{1}{\Vert T_1 \Vert} \sum_{u \in T_1} \max_{v \in T_2} \text{jaro\_winkler}(u, v)$

#### Feature 4: `feat_jaccard_token_addr`
*   **Method:** Standard Set Intersection over Union (IoU) of whitespace-split address tokens.

#### Feature 5: `feat_soft_tfidf_addr`
*   **Method:** Train a `TfidfVectorizer` globally on all cleaned addresses to get IDF weights. For two addresses, extract their tokens. Compute the similarity using Soft-TFIDF (where tokens are considered a match if their `jaro_winkler >= 0.85`), scaling by the TF-IDF weights.

#### Feature 6 & 7: Dense Semantic Cosine (`feat_cosine_bge_name`, `feat_cosine_bge_addr`)
*   **Method:** 
    1. Load `BAAI/bge-m3` via `SentenceTransformer`.
    2. Encode the names independently, and the addresses independently.
    3. The feature is the dot product (since vectors should be L2 normalized) between the vectors.
    *Optimization Note:* Encode unique strings first, store in a lookup dictionary or matrix, and then map them to the pairs. Do NOT run `.encode()` per pair!

#### Feature 8: `feat_digit_overlap`
*   **Method:** Extract all digits using `re.findall(r'\d+', text)`. Compute the Jaccard similarity of these digit sets. Great for matching building/suite numbers.

#### Feature 9: `feat_country_match`
*   **Method:** Binary flag. `1` if exact string equality, `0` otherwise. Do not one-hot encode.

### Step 4: Export Format
Save the final feature matrix as a memory-efficient format.
*   **Path:** `data/features/train_features.parquet`
*   **Columns:** `source1_entity_id`, `target_entity_id`, `feat_jaro_name`, ... (9 features), `is_match`
